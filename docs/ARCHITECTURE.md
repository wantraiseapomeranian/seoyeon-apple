# 구조와 데이터 무결성

## 요청 흐름

1. 브라우저가 공개 설정과 본인 쿠키 정보를 병렬 조회.
2. 닉네임 설정 시 플레이어와 복구 비밀 토큰 발급. 공개 ID와 표시 태그는 인증 수단이 아님.
3. 시작 API가 이전 active 세션을 무효화하고 seed, 규칙 스냅샷, 시작/만료 시각, KST 기간을 저장.
4. 브라우저와 서버가 동일한 TypeScript 엔진으로 보드를 생성.
5. 브라우저는 성공한 직사각형과 상대 시각만 기록. 실패는 상태를 바꾸지 않음.
6. 120초 또는 전체 클리어 후 종료 API로 로그 전송. 서버가 점수/콤보를 재계산.
7. D1 트랜잭션으로 세션 소진과 결과 저장. 결과 INSERT 트리거가 세 랭킹을 갱신.
8. 서버가 저장한 결과와 개인 전체 최고 기록의 순위를 반환. 재전송에는 이미 저장한 결과만 반환.

## 동시성과 멱등성

- 플레이어별 active 세션에 부분 유일 인덱스가 있다.
- 시작 API는 이전 세션 상태 변경과 새 세션 INSERT를 D1 batch로 묶는다.
- 종료 API는 active 조건 UPDATE에 임의의 submission_key를 기록하고, 같은 키로 획득한 세션만 결과로 INSERT한다.
- 뒤늦은 동시 요청은 상태 조건 UPDATE가 0행이므로 새 결과를 만들지 못한다.
- 결과의 PRIMARY KEY는 session_id. 동일 세션의 중복 결과는 DB에서도 거부한다.
- AFTER INSERT 트리거의 최고점 UPSERT는 기존 점수보다 클 때만 갱신한다. 동점/낮은 점수는 최초 달성 시각을 보존한다.
- 결과 INSERT 또는 랭킹 갱신이 실패하면 batch 전체가 롤백되므로 제출 가능한 상태가 유지된다.
- 통합 테스트가 동시 제출과 강제 저장 오류의 롤백을 실제 D1에서 검증한다.

## 경계와 기본값

- 모든 변경 요청은 정확한 동일 Origin + JSON이어야 한다. 쿠키는 HTTPS에서 Secure/HttpOnly/Host-only/Strict.
- API 응답은 no-store. 이름은 React 텍스트로 렌더링하며 SQL은 바인딩 파라미터를 쓴다.
- 요청 본문 24KB, 성공 액션 최대 85개, 정수 좌표/시각, 단조 증가 및 타일 합을 검증한다.
- IP 전체 API 180회/분, 플레이어 변경 API 40회/분, 시작 6회/분, IP 신규 플레이어 10회/10분.
- rate-limit 카운터는 D1 UPSERT RETURNING으로 원자적으로 증가한다. IP 원문 대신 해시를 버킷 식별자로 저장한다.
- 오류: 400 형식/로그, 401 미식별, 403 Origin, 404 소유하지 않은 세션 포함, 409 상태/쿨다운, 410 만료, 413 본문 제한, 429 요청 제한, 500 내부 오류.
- 클라이언트에서 서버 시간을 기준으로 경과 시간을 계산하되 네트워크 수신 지연은 실제 플레이 시간을 조금 줄일 수 있다. 서버 시간 검증이 최종 권위다.
- 현재 사진/규칙 설정은 서버 소스에서 관리. DB 관리 화면 없이 변경·배포하는 방식이다.

## 운영 범위

플레이어 복구 비밀은 쿠키에만 존재한다. 쿠키 분실 복구, 다른 기기 연동, 관리자 검토 화면, 실시간 치팅 탐지, 효과음/진동은 포함하지 않는다.
실측 데이터 없이 임계값을 확정된 밸런스로 취급하지 않는다.
